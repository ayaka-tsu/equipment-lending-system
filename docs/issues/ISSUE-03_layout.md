# ISSUE-03 共通レイアウトとアクセス制御

| 項目     | 内容                      |
| -------- | ------------------------- |
| 見積もり | 6h                        |
| 前提     | ISSUE-02                  |
| 優先度   | Must                      |
| ラベル   | `type:feature`, `area:ui` |

## 概要

全画面で使う共通ヘッダーと、ログイン状態・ロールによるアクセス制御を用意する。以降の画面はこのレイアウトの中に作る。

## 対象の仕様

- 機能要件：FR-03
- 非機能要件：NFR-S-06、NFR-E-02、NFR-E-03
- 画面：[03 画面一覧・共通仕様](../03_screen_list.md)（3.1〜3.3、3.8）、[SCR-90 エラー](../screens/SCR-90_error.md)
- デザイン：Figma の `Header` / `NavItem` / `Alert` コンポーネント

## やること

- [ ] 共通ヘッダー（システム名・メニュー・利用者名・ログアウト）を作る
- [ ] 管理者にだけ管理メニュー（管理ダッシュボード・申請・貸出管理・操作履歴）を表示する
- [ ] 表示中の画面のメニューを強調表示する
- [ ] 未ログインでログイン画面以外を開いたらログイン画面へリダイレクトする
- [ ] ログイン済みでログイン画面を開いたらホームへリダイレクトする
- [ ] 一般社員が `/admin` 以下を開いたら 403 の画面を表示する
- [ ] 存在しない URL では 404 の画面を表示する
- [ ] API が 401 を返したときに `/login?reason=expired` へ移動する共通処理を入れる
- [ ] 成功メッセージ・エラーメッセージの共通表示（画面上部・閉じるボタン）を作る

## 受入条件

- [ ] 一般社員のアカウントで `/admin` を開くと 403 の画面が出る
- [ ] 一般社員のアカウントで管理者向け API（例：`GET /api/loans`）を直接呼ぶと **403 が返る**（画面を隠すだけになっていない。NFR-S-06）
- [ ] 管理者のアカウントでは管理メニューが表示される
- [ ] ログアウト後に戻るボタンで前の画面に戻っても、ログイン画面へ移動する
- [ ] 幅375pxで横スクロールが出ない（NFR-E-02）

## 実装の手がかり

- 画面側の制御は `layout.tsx` でログイン状態を確認してリダイレクトする形にすると、画面ごとに書かずに済む。
- **リクエストの手前で共通処理を入れる場合、Next.js 16 では `middleware.ts` ではなく `proxy.ts` を使う**（`middleware.ts` は非推奨）。
- ヘッダーに出す利用者情報は `GET /api/auth/me` から取る。
- 403・404 の画面は Next.js の `not-found.tsx` や専用のコンポーネントで作る。
