# ISSUE-04 備品一覧・検索

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| 見積もり | 8h                                    |
| 前提     | ISSUE-03                              |
| 優先度   | Must                                  |
| ラベル   | `type:feature`, `area:api`, `area:ui` |

## 概要

社員が備品を検索し、借りられる状態かどうかを自分で確認できるようにする。総務部への「空いていますか」の問い合わせを減らすことが目的（課題2、KPI 2）。

## 対象の仕様

- 機能要件：FR-10
- 業務ルール：BR-01、BR-10
- 非機能要件：NFR-P-01、NFR-P-04、NFR-P-05、NFR-S-09
- 画面：[SCR-03 備品一覧](../screens/SCR-03_equipment_list.md)
- API：`GET /api/equipment`、`GET /api/categories`

## やること

- [ ] `GET /api/categories` を実装する（`sort_order` 昇順）
- [ ] `GET /api/equipment` を実装する（キーワード・カテゴリ・貸出可能のみ・ページング）
- [ ] 貸出可能数を計算する（保有数 − 引当数。BR-01）
- [ ] 削除済みの備品を一覧に出さない
- [ ] SCR-03 の画面を作る（検索フォーム・一覧・ページング）
- [ ] 検索条件とページ番号を URL のクエリ文字列に保持する
- [ ] 単体テスト：貸出可能数の計算、キーワードのエスケープ

## 受入条件

- [ ] キーワードで備品名・管理番号のどちらでも検索できる（大文字小文字を区別しない）
- [ ] キーワードに `%` や `_` を入れても、ワイルドカードとして扱われない
- [ ] 「貸出可能なもののみ」にチェックを入れると、貸出停止中と在庫0の備品が消える
- [ ] 貸出可能数が `2 / 3` の形式で表示され、シードのデータと一致する
- [ ] ページを移動しても検索条件が保たれ、URL を共有すると同じ結果が表示される
- [ ] 一覧の SQL が、表示件数に比例して増えない（開発サーバーのログで確認し、件数を PR に書く。NFR-P-05）
- [ ] ページングを DB 側で行っている（全件取得していない。NFR-P-04）

## 実装の手がかり

- 引当数は `loans` の `status IN ('pending','approved','lent')` の件数。備品ごとに1件ずつ数えると N+1 になるので、`GROUP BY` で一度に取るか、Prisma の `groupBy` を使う。
- Prisma の `contains` は `%` `_` をエスケープしないので、自分でエスケープする必要がある。
- 一覧の件数と行は別のクエリになる（`count` と `findMany`）。

- 備品詳細（ISSUE-05）
