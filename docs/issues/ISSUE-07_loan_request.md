# ISSUE-07 貸出申請

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| 見積もり | 9h                                    |
| 前提     | ISSUE-05                              |
| 優先度   | Must                                  |

## 概要

社員が備品の貸出を申請できるようにする。**このシステムで一番重要な処理**で、同時に申請されても在庫を超えて引き当ててはいけない（BR-02）。

## 対象の仕様

- 機能要件：FR-20
- 業務ルール：BR-01〜BR-05、BR-10、BR-14、BR-18
- 非機能要件：NFR-M-10、NFR-M-11、NFR-E-04
- 画面：[SCR-05 貸出申請](../screens/SCR-05_loan_request.md)
- API：`POST /api/loans`
- 処理の手順：[06 API設計書 4.2](../06_api_design.md)

## やること

- [ ] `POST /api/loans` を実装する（API設計書 4.2 の手順どおりに、1つのトランザクションで行う）
- [ ] 返却予定日の範囲チェック（申請日の翌日〜30日後。日本時間で判定。BR-05・BR-18）
- [ ] 貸出停止中の備品は 409 `EQUIPMENT_SUSPENDED`（BR-10）
- [ ] 同じ備品の未完了の申請があれば 409 `DUPLICATE_ACTIVE_LOAN`（BR-04）
- [ ] 貸出可能数が0なら 409 `OUT_OF_STOCK`（BR-02）
- [ ] 申請を `audit_logs` に `loan.request` として記録する
- [ ] SCR-05 の画面を作る（返却予定日の選択範囲、利用目的の文字数、エラーの表示）
- [ ] 単体テスト：返却予定日の範囲、重複申請の判定
- [ ] **同時申請のテスト**：残り1点の備品に2件の申請を同時に投げて、成功が1件・409 が1件になることを確かめる（NFR-M-11）

## 受入条件

- [ ] 申請すると申請詳細へ移動し、「貸出を申請しました。承認をお待ちください。」が表示される
- [ ] 申請した直後に備品詳細を開くと、貸出可能数が1つ減っている（BR-01）
- [ ] 当日や31日後を返却予定日にするとエラーになる
- [ ] 同じ備品に続けて申請すると `DUPLICATE_ACTIVE_LOAN` のメッセージが出る
- [ ] 同時申請のテストが CI で通る
- [ ] サーバーのタイムゾーンを変えても日付の判定が変わらない（`TZ=UTC npm test` で確認）

## 実装の手がかり

- 「数えてから INSERT」の間に他のリクエストが割り込むと在庫を超える。備品の行を `SELECT ... FOR UPDATE` でロックしてから数える。
- Prisma では `prisma.$transaction(async (tx) => { ... })` の中で `tx.$queryRaw` を使ってロックする。
- 部分ユニークインデックス `uq_loans_active_equipment_borrower` が最後の防御線になっている。一意制約違反（Prisma の `P2002`）を捕まえて 409 に変換する。
- 同時申請のテストは、`Promise.all` で2つの申請処理を同時に実行すると再現できる。テスト用の DB は開発用と同じ DB で構わないが、テストの最後に作ったデータを消すこと。
