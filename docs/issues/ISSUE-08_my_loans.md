# ISSUE-08 自分の申請一覧・申請詳細

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| 見積もり | 7h                                    |
| 前提     | ISSUE-07                              |
| 優先度   | Must                                  |
| ラベル   | `type:feature`, `area:api`, `area:ui` |

## 概要

社員が自分の申請の状況を確認できるようにする。申請詳細は、このあと承認・却下・取消などの操作を置く画面にもなる。

## 対象の仕様

- 機能要件：FR-21、FR-22
- 業務ルール：BR-06、BR-15
- 非機能要件：NFR-S-07
- 画面：[SCR-06 申請履歴](../screens/SCR-06_my_loans.md)、[SCR-07 申請詳細](../screens/SCR-07_loan_detail.md)
- API：`GET /api/me/loans`、`GET /api/loans/{loanId}`

## やること

- [ ] `GET /api/me/loans` を実装する（ステータス絞り込み、ページング、`created_at` 降順）
- [ ] `GET /api/loans/{loanId}` を実装する（本人と管理者だけが取得できる）
- [ ] 他人の申請を一般社員が指定した場合は **403 ではなく 404** を返す（NFR-S-07）
- [ ] 申請に `isOverdue`・`isDueSoon` を含める（BR-06・BR-15。日本時間で判定）
- [ ] `allowedActions` を返す（[API設計書 4.4](../06_api_design.md)）。中身の判定はこの Issue で作り、ボタンは ISSUE-09 で使う
- [ ] SCR-06 の画面を作る（タブ、一覧、ページング）
- [ ] SCR-07 の表示部分を作る（申請内容、処理の経過、却下理由）
- [ ] 単体テスト：延滞・返却期限間近の判定、`allowedActions` の組み立て

## 受入条件

- [ ] タブを切り替えると表示される申請が変わり、URL にも反映される
- [ ] 延滞している申請が「延滞」の赤いバッジで表示される（シードの延滞データで確認）
- [ ] 他人の申請 ID を URL に直接入れると 404 の画面になる
- [ ] 一般社員のアカウントで他人の申請の API を直接呼んでも 404 が返る（403 ではない）
- [ ] 却下された申請の詳細で、却下理由が表示される

## 実装の手がかり

- `isOverdue` / `isDueSoon` の判定は `src/lib/date.ts` に用意してある。
- `allowedActions` は「ログイン中の利用者がその申請に今できる操作」。状態遷移表（BR-07）と権限（BR-08・BR-16）から決まる。ここをサーバーにまとめておくと、画面側で同じ判定を書かずに済む。
- 存在しない申請と、見る権限がない申請は、どちらも同じ 404 にする（存在を知らせないため）。

## この Issue でやらないこと

- 操作ボタンと実際の状態変更（ISSUE-09）
- 管理者向けの全件一覧（ISSUE-10）
