# ISSUE-09 申請の取消・承認・却下・貸出記録・返却記録

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| 見積もり | 9h                                    |
| 前提     | ISSUE-08                              |
| 優先度   | Must                                  |
| ラベル   | `type:feature`, `area:api`, `area:ui` |

## 概要

申請の状態を変える操作をすべて実装する。誰がどの状態で何をできるかは状態遷移表で決まっていて、そこから外れた操作は受け付けない。

## 対象の仕様

- 機能要件：FR-23、FR-24、FR-25、FR-26、FR-27、FR-32
- 業務ルール：BR-07、BR-08、BR-09、BR-14、BR-16
- 非機能要件：NFR-M-10、NFR-S-06
- 画面：[SCR-07 申請詳細](../screens/SCR-07_loan_detail.md)
- API：`POST /api/loans/{loanId}/approve`・`/reject`・`/cancel`・`/lend`・`/return`
- 処理の手順：[06 API設計書 4.3](../06_api_design.md)

## やること

- [ ] 5つの API を実装する（状態遷移表のとおり）
- [ ] 現在の状態を更新条件に含めて UPDATE し、更新件数が0なら 409 `INVALID_STATUS_TRANSITION` を返す
- [ ] 管理者が自分の申請を承認・却下しようとしたら 403 `SELF_REVIEW_FORBIDDEN`（BR-08）
- [ ] 却下は理由（1〜200文字）を必須にする（BR-09）
- [ ] 取消の権限を分ける：本人は「申請中」「承認済」、管理者は「承認済」（BR-16）
- [ ] すべての操作を `audit_logs` に記録する（BR-14）
- [ ] SCR-07 に操作ボタンを置く。表示するボタンは API が返す `allowedActions` で決める
- [ ] 確認ダイアログと却下理由の入力ダイアログを作る
- [ ] 単体テスト：状態遷移表の全パターン（できる遷移・できない遷移）、自己承認の禁止

## 受入条件

- [ ] 管理者で承認 → 貸出記録 → 返却記録 と進められ、そのたびに状態バッジが変わる
- [ ] 承認済の申請を本人が取り消せる。貸出中の申請は本人が取り消せない
- [ ] 管理者が自分の申請を開くと「承認する」「却下する」が表示されない。API を直接呼ぶと 403 `SELF_REVIEW_FORBIDDEN` が返る
- [ ] 2つのタブで同じ申請を開き、片方で承認したあとにもう片方で承認すると `INVALID_STATUS_TRANSITION` になり、画面が最新の状態に更新される（この手順を PR に書く）
- [ ] 却下理由を空にすると送信できない（画面・API の両方で弾く）
- [ ] 返却を記録すると、その備品の貸出可能数が1つ増える
- [ ] 操作履歴に5種類の操作が記録されている

## 実装の手がかり

- 状態遷移の判定を画面側にも書くと二重管理になる。判定はサーバーに置き、画面は `allowedActions` を見るだけにする。
- `UPDATE loans SET status = 'approved' WHERE id = $1 AND status = 'pending'` の形にすれば、同時に操作されても片方だけが成功する。
- 権限のチェックとロールのチェックは別物。[API設計書 2.8](../06_api_design.md) のチェック順に従う。
