# ISSUE-10 申請・貸出管理一覧（管理者）

| 項目     | 内容                                  |
| -------- | ------------------------------------- |
| 見積もり | 7h                                    |
| 前提     | ISSUE-09                              |
| 優先度   | Must                                  |
| ラベル   | `type:feature`, `area:api`, `area:ui` |

## 概要

総務部が、全社員の申請と貸出の状況を1つの画面で確認できるようにする。延滞を翌日に把握できる状態にすることが目的（KPI 3）。

## 対象の仕様

- 機能要件：FR-28、FR-11（管理者向けの「現在の貸出状況」）
- 業務ルール：BR-06
- 非機能要件：NFR-P-01、NFR-P-04、NFR-P-05
- 画面：[SCR-09 申請・貸出管理](../screens/SCR-09_admin_loans.md)、[SCR-04 備品詳細](../screens/SCR-04_equipment_detail.md)の「現在の貸出状況」
- API：`GET /api/loans`

## やること

- [ ] `GET /api/loans`（管理者のみ）を実装する（状態・延滞のみ・申請者・備品・備品IDで絞り込み、ページング）
- [ ] 並び順を切り替える（延滞のみのときは返却予定日の昇順、それ以外は申請日時の降順）
- [ ] SCR-09 の画面を作る（検索フォーム・一覧・ページング。検索条件は URL に保持）
- [ ] SCR-04 に管理者向けの「現在の貸出状況」セクションを追加する（`equipmentId` で絞り込む）
- [ ] SCR-02・SCR-08 から `?status=pending` などを付けて遷移してきたとき、検索フォームの初期値に反映する

## 受入条件

- [ ] 「延滞のみ」にチェックを入れると、貸出中で返却予定日を過ぎた申請だけが、返却予定日の古い順に並ぶ
- [ ] 申請者の氏名・社員番号のどちらでも絞り込める
- [ ] 一覧から申請詳細へ移動して、そのまま承認・却下ができる
- [ ] 備品詳細（管理者）で、その備品を誰が借りているかが分かる
- [ ] 一般社員のアカウントで `GET /api/loans` を直接呼ぶと 403 が返る
- [ ] 一覧の SQL が表示件数に比例して増えない（申請者・備品を JOIN で一度に取る。NFR-P-05）

## 実装の手がかり

- 延滞の絞り込みは SQL の条件で行う（`status = 'lent' AND due_date < 今日`）。取得後にアプリ側で絞ると、件数とページングが合わなくなる。
- 「今日」は日本時間。DB 側で判定するなら `(now() at time zone 'Asia/Tokyo')::date` が使える。
- 検索条件の組み立ては、条件がない項目を無視する形にする（Prisma なら `where` に `undefined` を入れると無視される）。
