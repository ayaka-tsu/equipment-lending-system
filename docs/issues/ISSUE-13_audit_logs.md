# ISSUE-13 操作履歴の閲覧

| 項目     | 内容                                   |
| -------- | -------------------------------------- |
| 見積もり | 6h                                     |
| 前提     | ISSUE-09                               |
| 優先度   | **Should**（時間が足りなければ後回し） |
| ラベル   | `type:feature`, `area:api`, `area:ui`  |

## 概要

「誰がいつ何をしたか」を管理者が検索できるようにする。棚卸しで数が合わないときに経緯を追うために使う（課題4）。記録そのものは ISSUE-06・07・09 で実装済み。

## 対象の仕様

- 機能要件：FR-33
- 業務ルール：BR-14、BR-18
- 非機能要件：NFR-M-02
- 画面：[SCR-12 操作履歴](../screens/SCR-12_audit_logs.md)
- API：`GET /api/audit-logs`
- 期間の扱い：[06 API設計書 4.8](../06_api_design.md)

## やること

- [ ] `GET /api/audit-logs`（管理者のみ）を実装する（期間・操作種別・操作者で絞り込み、ページング、日時の降順）
- [ ] 期間の判定を日本時間で行う（終了日はその日を含む）
- [ ] 開始日が終了日より後なら 422 を返す
- [ ] SCR-12 の画面を作る（検索フォーム、一覧、対象と内容の組み立て、ページング）
- [ ] 単体テスト：期間の境界（終了日の23:59:59が含まれること）

## 受入条件

- [ ] 備品の編集の履歴で「状態：通常 → 貸出停止」のように変更内容が読める形で表示される
- [ ] 却下の履歴で却下理由が表示される
- [ ] 対象の申請・備品へのリンクから、該当の画面へ移動できる
- [ ] 終了日をその操作が行われた日に設定したとき、その日の操作が結果に含まれる
- [ ] 操作履歴を変更・削除する機能がない（NFR-M-02）

## 実装の手がかり

- `detail` は jsonb。操作種別ごとに入っている項目が違うので、画面側で種別ごとに組み立てる。形式は [05 テーブル定義書 3.6](../05_table_definitions.md) にある。
- 終了日は「翌日の 0:00（日本時間）より前」で比較すると、時刻の考慮が1か所で済む。

## この Issue でやらないこと

- CSV 出力（対象外）
