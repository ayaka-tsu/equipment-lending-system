# ISSUE-14 本番環境へのデプロイ

| 項目     | 内容                      |
| -------- | ------------------------- |
| 見積もり | 4h                        |
| 前提     | ISSUE-11                  |
| 優先度   | Must                      |
| ラベル   | `type:feature`, `area:db` |

## 概要

Vercel と Neon（PostgreSQL）で本番環境を用意し、`main` にマージすると自動でデプロイされる状態にする。

## 対象の仕様

- 非機能要件：NFR-M-06、NFR-M-07、NFR-S-14、NFR-S-16、NFR-A-03
- 技術スタック：[02 非機能要件定義書 8.3](../02_non_functional_requirements.md)

## やること

- [ ] Vercel にプロジェクトを作り、GitHub リポジトリと接続する（リーダーと一緒に行う）
- [ ] Vercel Marketplace から Neon を追加し、`DATABASE_URL` を設定する
- [ ] `APP_ORIGIN` に本番の URL を設定する
- [ ] 本番の DB にマイグレーションを適用する（`prisma migrate deploy`）
- [ ] 本番の DB にシードを投入する（パスワードは `SEED_PASSWORD` で開発用と変える）
- [ ] 本番の URL でログインし、主要な画面が動くことを確認する
- [ ] README に本番 URL と、デプロイの手順・注意点を追記する

## 受入条件

- [ ] 本番の URL でログインでき、備品一覧・申請・承認までひととおり動く
- [ ] `main` にマージすると自動でデプロイされる
- [ ] `.env` の値がリポジトリに入っていない（環境変数は Vercel の設定にある）
- [ ] 本番のパスワードが、リポジトリに書かれている開発用パスワードと異なる
- [ ] スリープからの復帰後、初回のアクセスに時間がかかることを README に注意として書いている（NFR-P-02）

## 実装の手がかり

- ビルド時にマイグレーションを流すと、失敗したときにデプロイが止まる。マイグレーションは手元から `prisma migrate deploy` で流すのが分かりやすい。
- Prisma Client の生成は `postinstall` で走るので、Vercel のビルドでも自動で行われる。
- Neon の無料プランは5分アクセスがないとスリープする。接続が来れば自動で復帰する。

## この Issue でやらないこと

- 独自ドメインの設定
- 監視・アラートの設定（対象外）
